# Codex“可”手动模式设计规格

- 日期：2026-07-20
- 项目：CodexQuickOK（界面名称：Codex 可）
- 平台：macOS
- 目标应用 Bundle ID：`com.openai.codex`

## 1. 摘要

把“Codex 可”改为用户主动启动的悬浮工具。用户点击 Dock 图标后，“可”按钮立即出现并保持
可见；单击按钮时，工具激活最近使用的 Codex 窗口，只操作该窗口的当前空输入框，写入一次
“可”并自动发送。

新版不再依赖 Hook 判断任务状态，不再跳转到指定任务，也不随登录自动启动。任何目标、焦点或
输入框状态不明确的情况都拒绝发送。

## 2. 已确认决策

- 采用手动启动模式，取消开机自启。
- 点击 Dock 图标后显示悬浮按钮。
- Codex 不在前台时，自动激活最近使用的 Codex 窗口。
- 当前输入框已有文字时拒绝发送，不覆盖也不追加。
- 采用 Accessibility API 直接操作当前 Codex 窗口，不使用模拟全局键盘输入。
- 保留灰色周额度光环、拖动位置和反馈动画。

## 3. 目标与非目标

### 3.1 目标

- 把“回复可并发送”缩短为一次点击。
- 启动和显示行为完全由用户控制，不再由 Codex 会话状态控制。
- 多个 Codex 窗口存在时，只操作最近使用窗口的当前输入框。
- 不破坏已有草稿，不向其他应用输入文字，不重复发送。
- 延续原有悬浮按钮、周额度光环和 Dock 启动体验。

### 3.2 非目标

- 不自动批准所有请求。
- 不处理 Codex 原生审批卡片。
- 不寻找、切换或打开其他 Codex 任务。
- 不使用剪贴板，不提供任意文本宏或全局键盘模拟。
- 不恢复 Hook 驱动的自动显示或隐藏。

## 4. 用户体验

### 4.1 启动与可见性

1. 用户点击 Dock 中的“Codex 可”。
2. 应用启动后立即显示 64 pt 悬浮按钮。
3. 按钮保持可见，不因 Codex 空闲、输出结束或未运行而自动隐藏。
4. 右键“隐藏按钮”后，用户再次点击 Dock 图标即可恢复。
5. 右键“退出”后应用终止；下次必须再次从 Dock 手动启动。

应用不注册新的登录项。新版首次启动时，如果发现旧版已注册主应用登录项，则注销该登录项，
完成一次性迁移。

### 4.2 按钮交互

- 单击：启动安全发送流程。
- 拖动超过 5 pt：只移动按钮，不发送。
- 发送进行中：锁定重复点击。
- 发送动作成功提交：短暂绿色反馈。
- 安全校验失败：红色反馈，并通过现有提示区域说明原因。
- 右键菜单：周额度详情、刷新额度、隐藏按钮、退出。

“隐藏按钮”菜单项注明“再次点击 Dock 图标可恢复”，避免用户误以为应用已经退出。

### 4.3 当前窗口定义

“当前最新打开的 Codex 界面”定义为：

- Codex 已在前台时，使用 Accessibility 的 focused window；
- Codex 不在前台时，先激活正在运行的 Codex 应用，再使用系统恢复的最近活动窗口；
- 不通过 `codex://threads/...`、任务标题、工作目录或会话 ID 导航；
- 无法得到唯一 focused window 时拒绝发送。

## 5. 系统设计

### 5.1 应用生命周期

`AppDelegate` 负责手动模式生命周期：

- 启动时创建悬浮面板、额度客户端和当前窗口发送器；
- 创建完成后无条件显示面板；
- 不创建 `SessionStateStore` 监视器，不根据 Hook 状态调用显示或隐藏；
- 不调用 `SMAppService.mainApp.register()`；
- 收到应用 reopen 事件时重新显示已隐藏的面板；
- 迁移时只注销本应用旧登录项，不更改其他登录项。

旧 Hook 可以保留在用户环境中，但新版应用不读取其状态文件，也不要求 Hook 才能工作。后续安装
流程不再把 Hook 作为运行前提。

### 5.2 当前窗口发送器

发送器不接收 `session_id`，流程固定为：

1. 获取 Bundle ID 为 `com.openai.codex` 的运行实例；不存在则失败。
2. 激活该实例并等待其成为前台应用。
3. 读取 Codex focused window。
4. 在该窗口内查找唯一、可编辑的对话输入框和唯一发送按钮。
5. 执行全部安全门检查。
6. 设置输入框值为“可”。
7. 对发送按钮执行一次 Accessibility press。
8. 返回成功反馈并释放点击锁。

发送器不会在结果不确定时自动重试。绿色反馈表示发送按钮已经成功执行，不表示服务器已经完成
处理。

### 5.3 安全门

以下条件必须同时满足：

- Accessibility 权限有效；
- Codex 正在运行；
- 激活后前台应用 Bundle ID 严格等于 `com.openai.codex`；
- focused window 唯一且属于 Codex；
- 未检测到 Codex 原生审批卡片；
- 对话输入框和发送按钮均可唯一识别；
- 输入框内容可读取且去除空白后为空；
- 当前没有另一笔发送操作进行中。

任一条件失败都不写入文字、不按 Return、不操作剪贴板。若“可”已经写入但发送按钮执行失败，
保留输入框内容供用户检查，不自动再次发送。

### 5.4 周额度

现有周额度客户端保持独立：

- 继续读取 Codex 七天额度窗口；
- 有效数据按剩余比例绘制光环；
- 数据缺失或不明确时显示灰色；
- 额度状态不决定按钮可见性，也不阻止发送。

## 6. 状态与错误反馈

| 场景 | 行为 |
| --- | --- |
| Codex 未运行 | 红色反馈；不自动启动 Codex，不发送 |
| Accessibility 权限缺失 | 红色反馈并引导到系统设置 |
| Codex 激活失败 | 红色反馈；不输入文字 |
| 多个窗口但 focused window 不明确 | 红色反馈；不猜测目标 |
| 原生审批卡片存在 | 提示“不支持此类审批”；不发送聊天文字 |
| 找不到唯一输入框或发送按钮 | 红色反馈；不发送 |
| 输入框已有草稿 | 提示“检测到未发送草稿”；不覆盖、不追加 |
| 写入“可”失败 | 红色反馈；不按发送按钮 |
| 发送按钮执行失败 | 保留“可”供检查；不自动重试 |
| 周额度不可用 | 光环为灰色；发送能力保持可用 |

## 7. 代码结构调整

- `AppDelegate`：移除 Hook 状态装配和默认登录项注册，增加手动显示及 reopen 恢复。
- `AppController`：从会话状态控制器改为简单的面板动作协调器，或由更小的手动模式控制器替代。
- `ApprovalSender`：改为当前窗口发送接口，不再要求目标会话或会话导航确认。
- `SystemCodexAutomation`：只保留激活 Codex 的职责；移除任务 URL 导航路径。
- `AccessibilityClient`：复用 focused window、输入框、发送按钮和原生审批卡片校验。
- `SessionStateStore` 与 Hook target：可暂时保留源码兼容旧安装，但不进入新版应用运行路径。
- 安装说明：删除 Hook 与登录项作为必需步骤的描述。

实现时优先缩小现有类型职责，避免在旧自动模式上叠加第二套状态机。

## 8. 测试策略

### 8.1 单元测试

- 启动后立即显示面板。
- reopen 事件恢复被隐藏的面板。
- 应用不注册登录项，并能注销自己的旧登录项。
- 点击时只调用一次当前窗口发送器。
- 发送中重复点击被忽略。
- 已有草稿、错误 Bundle ID、原生审批卡片、多个候选输入框均安全失败。
- 成功路径只写入一次“可”并只 press 一次发送按钮。
- 发送按钮失败后不重试。

### 8.2 集成与手动测试

- Codex 在前台：发送到 focused window。
- 其他应用在前台：自动切到最近使用的 Codex 窗口后发送。
- 多个 Codex 窗口：只操作系统恢复的最近活动窗口，不切换任务。
- Codex 未运行、权限撤销、输入框有草稿时不产生输入。
- Dock 冷启动显示按钮；运行中再次点击 Dock 可恢复隐藏按钮。
- 退出并重新登录 Mac 后应用不自动启动。
- 周额度正常、缺失和刷新失败时，按钮可见性与发送功能不受影响。

## 9. 验收标准

- 用户必须主动点击 Dock 图标才能启动应用。
- 启动后按钮立即可见，且不会因 Codex 会话状态自动隐藏。
- 单击按钮后，最近使用的 Codex 窗口空输入框收到且只收到一次“可”，随后自动发送。
- 操作过程中不会打开或切换到另一个 Codex 任务。
- 输入框已有内容或目标不明确时，原内容保持不变且不会发送。
- 不向 Bundle ID 非 `com.openai.codex` 的应用输入任何文字。
- 每次点击最多执行一次发送动作；失败时不自动重试。
- 旧登录项被安全移除，重启系统后应用不会自行启动。
- 灰色周额度光环和拖动位置继续正常工作。

## 10. 风险与缓解

- Codex 的 Accessibility 层级可能随版本变化：元素无法唯一识别时安全失败，并以测试夹具覆盖已知结构。
- macOS 激活应用后 focused window 更新可能有短暂延迟：使用有上限的短等待轮询，不在超时后猜测。
- 发送按钮执行成功不等于网络接收成功：不自动重试，避免重复消息。
- 辅助功能权限能力较高：每次发送前重新校验前台 Bundle ID 和窗口归属。
- 旧 Hook 可能继续写入状态文件：新版不读取这些文件，因此不会影响显示或发送。
